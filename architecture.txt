└─────────────────────────────────────────────────────────┘Flow, top to bottom:

User uploads a scanned land record page through the Next.js frontend.
Request hits the Express API on Render, authenticated via Supabase Auth (checks role — officer vs reviewer).
Backend saves the raw file to S3/Supabase Storage, then sends it to Google Cloud Vision for OCR (falling back to self-hosted Tesseract if you're over the free quota).
Extracted raw text goes to the Claude/GPT API, which structures it into fields — owner name, Khasra/Khata number, plot area, village, land class — each with a confidence score.
The validation engine (inside the Express API) runs business rules: area-sum checks, duplicate detection, and flags any low-confidence field.
Structured records land in MongoDB Atlas; verified plot boundaries get geo-referenced into Postgres/PostGIS and rendered on a Leaflet map.
Low-confidence records route back to the frontend's HITL review dashboard for a human to approve or correct before final commit.
